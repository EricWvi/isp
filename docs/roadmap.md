# IP 池服务 Roadmap

## 1. 目标

构建一个单机运行的 IP 池服务，对本机应用暴露一个 SOCKS5 入口，并通过可扩展的 Provider 管理上游 SOCKS5 代理。

服务在任意时刻维护一个全局当前代理。所有新建 TCP 连接默认复用该代理，只有用户明确操作或自动切换策略确认当前代理不可用时才切换，以尽量减少出口 IP 变化。已有连接不因切换而中断。

首版只接入 `proxy-seller`。它暂不调用供应商接口，上游代理由 YAML 配置或管理页面维护。

## 2. 首版范围

### 2.1 包含

- 一个仅支持 TCP `CONNECT` 的本地 SOCKS5 入口，监听端口必须大于等于 `30000`。
- 上游代理使用 SOCKS5，支持无认证、用户名密码认证两种方式；无认证场景可由供应商按出口 IP 授权。
- 一个全局当前代理，以及手动选择、手动轮换和自动故障切换。
- Provider 环形选择，以及由各 Provider 自己实现的内部 IP 选择逻辑。
- 每个代理独立进行可用性检测、失败计数和退避调度。
- YAML 保存静态配置和代理清单，SQLite 保存可恢复的运行时状态。
- 管理页面展示状态并维护代理，视觉使用 shadcn/ui 默认风格。
- 前端构建产物位于 `frontend/dist`，通过 Go `embed` 打入单一可执行文件。

### 2.2 不包含

- SOCKS5 `UDP ASSOCIATE`。
- Proxy Seller SDK 或远程接口集成。
- 多节点状态同步或高可用部署。
- 按请求、域名、客户端或流量特征制定不同的选路规则。
- 当前连接的无感迁移；代理切换只影响新连接。
- 对公网开放管理页面及相应的多用户权限系统。

## 3. 核心行为

### 3.1 全局当前代理

- 服务只维护一个全局当前代理，标识由 `provider_id + proxy_id` 组成。
- 每个新的 SOCKS5 TCP 连接读取一次当前代理快照，并在该连接生命周期内保持不变。
- 服务重启后优先从 SQLite 恢复上次选择；只有对应代理已从 YAML 删除或禁用时，才重新选择。
- 当前代理处于 `unknown` 或短暂失败状态时不立即切换，避免网络抖动造成出口 IP 频繁变化。
- 当前代理确认不可用且自动切换已开启时，才自动选择下一个可用代理。
- 自动切换关闭时，即使当前代理不可用也不自动更换；新连接直接失败，等待用户手动处理。
- 没有可用代理时直接返回 SOCKS5 失败，不允许回退到本机直连。

### 3.2 自动切换开关

- 开关从关闭变为开启时，继续使用当前代理，不主动轮换。
- 开关开启后，仅在当前代理确认不可用时触发自动切换。
- 手动选择或手动轮换不会修改自动切换开关。
- 自动切换状态写入 SQLite，服务重启后保持不变。

### 3.3 手动操作

- **手动选择**：用户指定一个已启用的代理并立即设为全局当前代理；只影响新连接。
- **手动轮换**：从当前选择之后寻找下一个可用代理；没有其他可用代理时保持当前选择并返回明确提示。
- **新增代理**：写入 YAML 并加入运行时，初始状态为 `unknown`，立即安排一次检测，但不会自动替换当前代理。
- **编辑代理**：写入 YAML；连接信息变化后清除旧检测结论并重新检测。如果编辑的是当前代理，后续新连接使用新配置。
- **删除代理**：已有连接继续使用创建时的代理快照；如果删除的是全局当前代理，则按自动切换规则选取替代项，否则进入无当前代理状态。
- **启用/停用**：停用的代理不参与检测和选择；停用当前代理与删除当前代理采用相同的重新选择规则。

### 3.4 Provider 选择

全局选路模块只在以下事件发生时选择代理，而不是在每个连接到来时选择：

- 首次启动且无法恢复有效的当前代理；
- 用户手动轮换；
- 当前代理确认不可用且自动切换开启；
- 当前代理被删除或停用。

选择过程分为两层：

1. 从当前 Provider 的下一个位置开始，按环形顺序寻找存在可用代理的 Provider。
2. 由选中的 Provider 在自己的候选代理中决定具体 IP。

环形遍历一周仍无候选时返回“无可用代理”。当前只有一个 `proxy-seller` Provider 时，环形选择仍然生效，具体轮换由该 Provider 的内部实现完成。

## 4. 模块与接口

### 4.1 SOCKS 网关模块

职责：

- 接受本地 SOCKS5 TCP `CONNECT` 请求。
- 获取全局当前代理快照。
- 使用可选认证连接上游 SOCKS5，再透传客户端与目标站点之间的双向流量。
- 将上游连接错误报告给健康检查模块，用于触发提前复检，而不是自行改变当前代理。

该模块不知道 Provider 的环形顺序、健康判定阈值或 YAML 写回方式。

### 4.2 全局选路模块

职责：

- 持有并串行更新全局当前代理。
- 实现恢复、手动选择、手动轮换和自动故障切换。
- 保证并发故障事件只触发一次有效切换。
- 在选择改变后持久化 SQLite，并向管理页面发布最新状态。

模块对 SOCKS 网关提供一个小接口：读取不可变的当前代理快照。复杂的 Provider 遍历和切换策略隐藏在模块内部。

### 4.3 Provider 模块

Provider 的公共接口只表达全局选路真正需要的能力：

- 返回稳定标识和展示信息。
- 判断是否存在可用候选。
- 根据 Provider 自己的策略选择首个或下一个可用代理。

代理商特有的获取、鉴权、刷新和内部 IP 选择逻辑留在各自实现中，不进入全局选路模块。首版 `proxy-seller` 从 YAML 读取静态列表，并按稳定顺序在其可用代理间轮换。

公共代理记录至少包含：

- 稳定的 `proxy_id`；
- 地址和端口；
- 可选用户名、密码；
- 是否启用；
- 用于页面展示的名称或备注。

`proxy_id` 不从可变的 `IP:端口` 临时推导，确保编辑连接信息后仍能关联 SQLite 中的运行状态。

### 4.4 健康检查模块

职责：

- 通过指定上游 SOCKS5 代理访问配置的检测 URL。
- 按代理维护 `unknown`、`healthy`、`suspect`、`unavailable` 状态。
- 管理连续成功/失败次数、最近错误和下次检测时间。
- 当前代理变为 `unavailable` 时通知全局选路模块，但不直接修改选择。
- SOCKS 网关报告连接失败时提前安排复检，仍沿用统一的健康判定阈值。

默认策略：

- 正常检测间隔在 5 至 8 分钟之间随机生成，避免所有代理同时探测。
- 单次检测超时默认 15 秒。
- 成功建立代理链路并从检测 URL 收到 HTTP 响应即视为成功，不限定必须为 `2xx`。
- 连续 3 次失败后标记为 `unavailable`，单次或两次失败标记为 `suspect`。
- 失败后的下一次检测采用指数退避并保留随机抖动，上限默认 1 小时；检测成功后清零失败计数并恢复 5 至 8 分钟间隔。
- 阈值、超时、检测 URL 和退避上限均可通过 YAML 配置。

### 4.5 配置模块

YAML 是以下内容的事实来源：

- HTTP 和 SOCKS5 监听地址；
- 健康检查参数；
- Provider 定义；
- 代理地址、端口、认证信息、启停状态和备注。

管理页面的写操作统一经过配置模块。写回要求：

- 使用两个空格缩进，输出稳定、便于人工阅读；
- 不要求保留原注释；
- 先写同目录临时文件、校验可重新加载后再原子替换；
- 串行处理并发修改，避免后写请求覆盖先写请求；
- 文件写入失败时不改变内存配置，并向页面返回明确错误。

首版不自动监听外部文件修改；用户直接编辑 YAML 后需要重启服务生效。

### 4.6 运行状态存储模块

SQLite 是以下运行时数据的事实来源：

- 全局当前代理；
- 自动切换开关；
- 每个代理的健康状态；
- 连续成功/失败次数；
- 最近检测时间、结果和错误摘要；
- 下次检测时间及退避阶段；
- 最近一次切换的原因和时间。

启动时先加载 YAML，再用稳定 ID 关联 SQLite 状态。SQLite 中找不到对应 YAML 配置的孤立记录不参与选择，可在后续维护阶段清理。

### 4.7 管理 Web 模块

前端使用 React、TypeScript、Vite、Tailwind CSS 和 shadcn/ui 默认主题。首版页面包含：

- 当前代理卡片：Provider、IP、端口、健康状态、选中时间、切换原因。
- 自动切换开关。
- 手动轮换操作。
- Provider 与代理列表：状态、最近检测、连续失败次数、下次检测、启停状态。
- 新增、编辑、删除、启用、停用和手动选择代理。
- 对无可用代理、YAML 写入失败、健康检查失败给出明确反馈。

生产构建输出到 `frontend/dist`。Go 使用 `go:embed` 嵌入该目录，并为前端路由提供 SPA fallback。发布产物只需要 Go 可执行文件、YAML 配置和 SQLite 数据文件。

## 5. 配置草案

字段名称可在实现阶段微调，但配置职责保持不变：

```yaml
server:
  http_listen: 127.0.0.1:8080
  socks5_listen: 127.0.0.1:30001
  database: ./data/isp.db

health_check:
  url: https://www.gstatic.com/generate_204
  interval_min: 5m
  interval_max: 8m
  timeout: 15s
  failure_threshold: 3
  backoff_max: 1h

providers:
  - id: proxy-seller
    type: proxy-seller
    enabled: true
    proxies:
      - id: proxy-seller-01
        name: primary
        host: 192.0.2.10
        port: 1080
        enabled: true
        username: ""
        password: ""
```

启动时必须校验：监听端口范围、Provider ID 和代理 ID 唯一性、主机与端口合法性、时间范围，以及健康检查配置。认证字段为空表示使用无认证模式。

## 8. 首版验收场景

- [ ] 无认证和用户名密码认证的上游 SOCKS5 都能完成 TCP 转发。
- [ ] 多个并发连接使用同一个全局当前代理，不会按连接轮换出口 IP。
- [ ] 手动选择后，新连接使用指定代理，已有连接不中断，自动切换开关保持原值。
- [ ] 手动轮换选择下一个可用代理；没有其他候选时保持当前代理。
- [ ] 自动切换从关闭变为开启时不立即换 IP；当前代理连续失败达到阈值后才切换。
- [ ] 自动切换关闭且当前代理不可用时，请求失败且不会直连。
- [ ] 新增、编辑、删除和启停操作能安全写回格式清晰的 YAML。
- [ ] 服务重启后恢复当前代理、自动开关、健康状态和退避进度。
- [ ] 所有代理不可用时，SOCKS5 请求明确失败，页面显示无可用代理。
- [ ] 前端静态资源已嵌入 Go 二进制，运行时不依赖独立的 `dist` 目录。
